## STEP 1 — Observation (관찰)

### 질문

1. 현재 우리가 해결하려는 상황은 무엇인가?
2. 왜 4×4 마방진 문제를 다루는가?
3. 이 문제는 어떤 학습 또는 시스템 설계 맥락에서 등장하는가?

*(「마방진을 만든다」는 표현 대신, 상황을 관찰 관점으로 서술)*

### 1. 현재 우리가 해결하려는 상황

**관찰**

누군가는 **4×4 격자에 1부터 16까지의 정수를 한 번씩 배치했을 때**, 행·열·대각선 합이 모두 동일한지 **확인하거나**, 그 조건을 만족하는 배치를 **찾거나**, 그 과정을 **프로그램으로 재현·검증**하려는 상황에 있다.

관찰 관점으로 재서술하면:

| 관찰 축 | 내용 |
|---------|------|
| **입력/출력** | 16칸 격자와 16개의 서로 다른 숫자(또는 그에 상응하는 규칙)가 주어지거나 생성된다 |
| **제약** | 여러 「줄」(가로 4, 세로 4, 대각 2)에 대한 **합이 하나의 목표값과 일치**해야 한다 |
| **불확실성** | 사람이 손으로 채운 격자인지, 알고리즘이 채운 격자인지, 「맞는지 검사만」 하는지, 「맞는 배치를 탐색」하는지는 아직 명시되지 않았다 |
| **맥락** | 프로젝트 저장소가 비어 있는 상태이므로, **문제를 코드로 옮기기 전에 「무엇을 관찰할 것인가」를 정리하는 단계**에 있다 |

**한 줄:** 해결 대상은 「숫자 퍼즐」 자체라기보다, **제약이 많은 작은 격자 배치 문제를 어떤 역할(학습, 도구, 데모)로 다룰지 아직 열린 채로 놓인 상황**이다.

### 2. 왜 4×4 마방진 문제를 다루는가

**관찰 (가설 — 사용자 확인 전까지 확정 아님)**

| 관찰 가능한 이유 | 설명 |
|------------------|------|
| **규모가 작음** | 3×3보다 제약·탐색·표현이 한 단계 복잡하지만, 여전히 손·코드로 전체를 다루기 쉬운 크기 |
| **짝수 차수** | 홀수 차수와 **구성 규칙이 달라** 「한 가지 공식만 외우면 된다」가 성립하지 않음 |
| **교육·연습** | 배열, 반복, 조건, 합 검증, 2차원 자료, 불변 조건 검사 등 **프로그래밍 기초를 한 주제에 묶기** 좋음 |
| **검증 vs 생성** | 「조건 만족 여부」는 단순하고, 「만족하는 배치 찾기/나열」은 난이도가 올라가 **요구사항을 나누기** 좋음 |
| **주제의 명확성** | 수학·퍼즐 문화에서 익숙한 이름이라 **문제 범위를 짧게 공유**하기 쉬움 |

**관찰 결론:** 4×4를 고른 이유는 **「작지만 짝수 차수라서 설계·학습의 경계가 보이는 최소 사례」**일 가능성이 크다.

### 3. 학습 · 시스템 설계 맥락

**학습 맥락**

- 알고리즘 입문: 완전 탐색, 백트래킹, 제약 만족의 작은 실습 모델
- 자료구조: 2차원 배열, 불변 조건, 유효/무효 판정
- 수학·조합: 대칭, 패턴, 불변량(마법 상수 34) — 논리와 실행의 대응 연습
- 테스트·명세: 「행·열·대각 합이 같다」를 **검증 가능한 요구사항**으로 쓰기 좋음

**시스템·설계 맥락**

- 도메인 모델: 격자, 줄(행/열/대각), 제약, 검증기 등 **경계 나누기** 연습
- 파이프라인: 생성 → 검증 → 표시, 또는 입력 → 검증 → 피드백
- 요구사항 분리: 필수(1~16 한 번씩, 합 일치) vs 선택(동치, 전체 열거)
- 확장 압력: 3×3, 5×5, n×n 등으로 일반화 여지

**이 대화의 맥락**

구현 전 **문제 정의·관찰·요구사항 명확화**를 연습하는 엔지니어링/학습 프로세스에 가깝다.

### STEP 1 한 줄 요약

**4×4 격자에 16개의 서로 다른 수를 놓았을 때, 여러 방향의 합이 하나로 맞는지를 다루는 작은 제약 문제**가, **짝수 차수·교육·검증/생성 분리** 때문에 선택되었고, 현재는 **그 문제를 프로그램으로 옮기기 전에 상황과 동기를 관찰하는 단계**에 있다.

## STEP 2 — Why #1

### 질문

**Q:** 왜 마방진을 완성해야 하는가?

**방법:** 답(A)을 가정하고, 그 답에서 드러나는 불편함·구조적 문제를 분석한다.

### 가정한 답 (A)

> **「4×4 마방진을 완성해야 하는 이유는, 주어진 규칙(1~16 각 한 번, 행·열·대각 합 동일)을 만족하는 배치가 『정답』인지 학습자가 스스로 확인할 수 있게 하기 위해서이다. 즉, 수업·자기학습용으로 『맞게 채웠는지』를 즉시 판별하는 연습 도구가 필요하다.」**

### A에서 드러나는 불편함 (사용자·학습자)

| 불편 | 관찰 |
|------|------|
| **수동 검산 부담** | 10개 합을 손으로 더하면 실수·지루함 — 「완성했다」와 「실제로 맞다」 사이 **검증 공백** |
| **부분 오류 발견 어려움** | 한 줄만 틀려도 전체 무효 — 어느 줄·칸이 원인인지 **피드백 없이** 수정 방향 찾기 어려움 |
| **마법 상수(34) 모름** | 잘못된 기준으로 검산하거나 「거의 맞는」 배치를 정답으로 착각 |
| **짝수 차수 구성 난이도** | 3×3과 달리 한 가지 기억만으로 채우기 어려워 「완성」 자체가 먼저 막힘 |
| **정의 혼동** | 「숫자만 1~16」 vs 「합까지 동일」 — **완성의 기준**이 사람마다 갈림 |

### A에서 드러나는 구조적 문제

| # | 구조적 문제 | 설명 |
|---|-------------|------|
| 1 | **목표 이중성: 완성 vs 검증** | 표면은 완성, 실제 필요는 판별 — 생성 문제인지 판정 문제인지 한 문장에 묶이면 요구사항 흔들림 |
| 2 | **성공 기준이 외부에 있음** | 정답은 격자 내부가 아니라 불변 조건 — **규칙 엔진(판정)** 이 전제인데 A만으로는 경계가 드러나지 않음 |
| 3 | **4×4 짝수 차수 특성** | 구성법이 홀수와 다름 — 해·대칭·동치 — 「하나의 정답」 vs 「아무 유효 배치」 충돌 가능 |
| 4 | **완성 경로 vs 완성 결과** | 자동 완성만 하면 **학습 목적(스스로 확인)** 과 충돌 — 누가 채우는가가 A에 없음 |
| 5 | **검증 세분화 부재** | 학습에는 어느 제약이 깨졌는지 필요 — A만 있으면 단일 맞음/틀림으로 수렴 |
| 6 | **범위 creep** | 힌트·게임·전체 해·확장 — 핵심 불편(검산·피드백) 희석 |

### STEP 2 압축

| 관점 | 내용 |
|------|------|
| **겉으로 듣는 Why** | 규칙을 만족하는 4×4 배치에 도달해야 한다 |
| **실제 구조적 Why** | 그 배치가 규칙을 만족하는지 **신뢰할 수 있게 판별**해야 학습이 이어진다 |
| **숨은 갈등** | 완성(생성) · 검증(판정) · 설명(교육)이 한 목표로 묶여 있음 |

## STEP 3 — Why #2

### 질문

**Q:** 왜 단순 계산이 아니라 프로그램으로 구현하는가?

**관점:** 반복 가능성 · 검증 자동화 · 오류 방지 · 규칙 기반 사고 훈련

### 전제

「단순 계산」= 손계산·종이·계산기로 합을 더하고 맞는지 보는 방식  
「프로그램」= 규칙을 실행 가능한 형태로 옮겨 기계가 같은 판단을 수행

### 1. 반복 가능성

- 4×4 검산만 해도 **10번의 합 비교** 반복
- 사람은 매번 절차·속도·집중도가 달라짐
- 프로그램: 동일 입력 → 동일 절차·결과, 다회·다인 재검사, 판단 일관성

**구조적 한계 (손계산):** 반복 시 검산 피로, 「거의 맞음」과 「완전히 맞음」 경계 흐림

### 2. 검증 자동화

- STEP 2 병목: 「완성했다」와 「규칙 만족」 사이 검증 공백
- 여러 제약(중복, 합, 10줄)을 한 번에 적용 → 즉시 피드백 → 학습 루프 단축
- 말로 전달된 규칙과 실행 결과 간극 축소

**구조적 한계:** 부분 검증을 전체 통과로 오인

### 3. 오류 방지

- 산술 실수, 잘못된 마법 상수, 중복·누락 미확인, 근사 통과
- 프로그램: 절차 외부화, 체크리스트 고정, 경계 조건 명시적 거부

**한계:** 구현 자체의 오류 가능 — **사용자 검산 오류** vs **명세·테스트 책임** 이중화

### 4. 규칙 기반 사고 훈련

- 자연어 한 문장 → 정의·불변량·구조 등 **여러 규칙의 교차**
- 규칙 분해, 명시성, 일반화(n×n), 생성 vs 판정 분리

**주의:** 목적이 산수만이면 프로그램이 규칙 적용 연습을 대체 — **역할 분담**(사람: 배치, 기계: 판정) 필요

### 네 관점 요약표

| 관점 | 단순 계산의 한계 | 프로그램을 쓰는 이유 |
|------|------------------|----------------------|
| 반복 가능성 | 회차마다 기준 흔들림 | 동일 규칙·무한 재검사 |
| 검증 자동화 | 부분·사후 검산 | 전 제약 한 번에 판정 |
| 오류 방지 | 산술·누락·근사 통과 | 검증 절차 외부화 |
| 규칙 기반 사고 | 규칙이 암묵적 | 규칙 분해·명시·분리 훈련 |

### STEP 3 메시지

STEP 2 병목(검증·피드백)에 대해 손계산은 반복·완전성·명시성에서 약하고, 프로그램은 **반복 가능한 자동 검증 + 규칙의 명시화**로 Why #1을 뒷받침한다.

**새 구조적 문제:** 목표가 「마방진 이해」에서 「코드 작성」으로 drift — **프로그램의 최소 역할(예: 판정기만)** 을 비목표와 함께 고정할 필요

## STEP 4 — Why #3 (핵심 발견)

### 질문

**Q:** 왜 이 문제를 TDD 방식으로 설계하려 하는가?

- 무엇이 통제되어야 하는가?
- 어떤 불변 조건이 존재하는가?
- 왜 입력/출력이 명확해야 하는가?

### TDD의 의미 (본 보고서)

테스트를 먼저 쓰는 기법을 넘어, **요구사항(규칙)을 실행 가능한 명세로 고정하고, 구현이 그 명세를 깨지 않게 하는 설계 방식**.

### 1. 무엇이 통제되어야 하는가

| 통제 대상 | 이유 |
|-----------|------|
| 판정 기준 | 규칙 위반 여부가 핵심 산출물 |
| 검증 범위 | 부분 검증 방지 — 행·열·대각·중복·범위 누락 없음 |
| 마법 상수(34) | 잘못된 목표 합 방지 |
| 입력 형태 | 정의 밖 입력 명시적 실패 |
| 생성 vs 검증 | 테스트·책임 분리로 drift 방지 |
| 회귀 | 알려진 유효/무효 격자 고정 |
| 구현 정확성 | 기계 판정의 신뢰 |

**통제하지 않아도 되는 것:** 채우는 순서, 내부 표현, 구성 전략 — **판정 결과만 동일**하면 됨

### 2. 불변 조건 (STEP 4 관점)

**도메인**

- I-D1: 4×4, 16칸
- I-D2: 1~16 각 정확히 한 번
- I-D3: 검사 줄 = 4행 + 4열 + 2대각
- I-D4: 유효 시 10줄 합 동일 (= 34)

**판정기**

- I-P1: 동일 입력 → 동일 결과
- I-P2: 「유효」는 모든 필수 검사 후에만
- I-P3: 위반 시 절대 유효 아님
- I-P4: 판별이 입력 배치를 변경하지 않음

**명세**

- I-S1: 입력 완전성 정책과 판정 일치
- I-S2: 출력 의미 회귀 시 유지

### 3. 왜 입력/출력이 명확해야 하는가

**입력:** 재현 가능한 픽스처, 경계(미완성·빈 칸) 정책, 코어 vs UI 책임 분리

**출력:** 성공 기준 고정 — 최소 유효/무효, 확장 시 위반 설명(STEP 2 피드백)

**최소 I/O 계약 (문제 정의 수준)**

| 구분 | 내용 |
|------|------|
| 입력 | 4×4, 1~16 순열 (미완성은 별 정책) |
| 출력 | 유효 여부; 선택: 공통 합, 실패한 줄, 중복 값 |

### STEP 4 한 줄

4×4는 **불변 조건·입출력이 작고 명확**해, 규칙을 테스트(계약)로 먼저 고정하는 방식이 **요구사항 drift·부분 검증·완성/검증 혼동**을 가장 싸게 막는다.

## STEP 5 — 진짜 문제 정의

### 1. 표면 문제 정의 (잘못된 정의)

> **「4×4 마방진을 완성하는 프로그램을 만든다.」**

| 문제 | 설명 |
|------|------|
| 목표가 결과에만 묶임 | 누가·어떻게·하나만인지 불명확 |
| 검증 누락 | 실제 병목은 판별 |
| 범위 폭발 | 생성·게임·열거·확장으로 확장 |
| 성공 기준 없음 | 실패 정의 없음 |
| 학습 목적 희석 | 도구/과제/연습 미구분 |

### 2. 개선된 문제 정의 (정확한 정의)

#### 한 문장

> **「4×4 격자에 1부터 16까지 각각 한 번씩 배치된 상태가, 행·열·대각선에 대한 합 규칙을 모두 만족하는지를 일관되게 판별하고, 그 판별 기준을 반복 가능한 방식으로 고정하는 것이 문제이다.」**

#### 풀어 쓴 정의

| 요소 | 내용 |
|------|------|
| 대상 | 4×4 격자, 1~16 각 한 번 |
| 핵심 행위 | 규칙 만족 **판별** (선택: 위반 **설명**) |
| 품질 | 동일 판단, 검사 누락 없음 |
| 경계 | 채우기·생성·게임·시각화는 본 문제 아님 |
| 성공 | 유효/무효/(정책상) 미완성이 사전 기준으로 구분 |
| 실패 | 부분 확인, 기준 없는 「대충 맞음」, 판단 불일치 |

#### 비목표

- 특정 구성 방법 강제
- 모든 유효 배치 나열
- n×n 일반화를 1차 목표로 둠
- UI·속도를 1차 목표로 둠

### 3. 핵심 Invariant (STEP 5 확정본)

**도메인**

| ID | Invariant |
|----|-----------|
| I-1 | 4×4, 칸당 하나의 값 |
| I-2 | 1~16, 16개 서로 다름 |
| I-3 | 검사 줄: 4행 + 4열 + 2대각 |
| I-4 | 유효 시 10줄 합 동일 |
| I-5 | 1~16 전체 사용 시 공통 합 = 34 |

**판정기**

| ID | Invariant |
|----|-----------|
| I-6 | 동일 입력 → 동일 판정 |
| I-7 | 「유효」는 I-2~I-4 전부 검사 후 |
| I-8 | I-2 위반 → 비유효 |
| I-9 | I-4 위반 → 비유효 |
| I-10 | 판별이 배치를 변경하지 않음 |

**명세·계약**

| ID | Invariant |
|----|-----------|
| I-11 | 입력 완전성 정책이 판정과 일치 |
| I-12 | 출력 의미가 회귀 시에도 유지 |

**Invariant 아님:** 구성 방법, 해 개수·동치, 누가 채우는지

### 4. 실제로 훈련하려는 사고 능력

| # | 능력 |
|---|------|
| 4.1 | **규칙 분해·계약** — 완성 vs 유효 구분, 충분/필요 조건 |
| 4.2 | **불변량 인식** — 도메인 불변 vs 표현 |
| 4.3 | **판정과 생성 분리** |
| 4.4 | **입출력·경계 명확화** — 미완성/무효/유효 |
| 4.5 | **검증 우선·완전 검사** |
| 4.6 | **명세 고정·회귀 의식** — 비목표 인지 |
| 4.7 | **규칙 외부화** — 사람·고정 절차 역할 분담 |

### 표면 vs 개선 요약

| 구분 | 표면 (잘못된) | 개선 (정확한) |
|------|----------------|----------------|
| 초점 | 완성·생성 | 판별·규칙 고정 |
| 성공 | 격자 채움 | 일관된 판정 |
| 산출물 | 정답 격자 | 유효성 (+ 위반 설명) |
| 훈련 | 퍼즐 풀이 | 규칙·불변·계약·검증 사고 |

## 다음 단계 제안

아래는 본 보고서 범위 밖이며, 문제 정의를 이어갈 때 검토할 항목이다.

1. **미완성 격자 정책** — 무효와 별도 상태로 둘지, 단일 「비유효」로 둘지

4. **성공 기준 체크리스트** — STEP 5 Invariant를 검수 항목으로 전환
5. **구현 착수 전** — 판정기만 1차 범위로 고정할지 문서화
